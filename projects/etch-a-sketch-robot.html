Etch A Sketch Robot Artist

A Kinova Gen3 arm draws on a classic Etch A Sketch by gripping and turning its two knobs, one at a time. The same skill code runs on a toy model, in MuJoCo and on the real arm. The MuJoCo version runs live in your browser.

A robot arm that draws on an Etch A Sketch has to do it the way a person does: by turning two knobs. This project builds that skill in simulation first, with the same code written to run unchanged on a real Kinova Gen3.

Why this is a hard manipulation problem

An Etch A Sketch gives the robot almost nothing to work with.

  • One gripper, two knobs. The arm can turn only one knob at a time, so every drawing is a single unbroken path of horizontal and vertical strokes. Each change of knob costs about three seconds.
  • The pen is invisible. Only the line it leaves can be seen, and it is a faint grey line on a reflective grey screen.
  • The knobs have backlash. After a reversal, the knob turns about 27 degrees before the pen moves again. A controller that ignores this draws every corner about 2 mm short.
  • Mistakes are permanent. The only eraser is turning the toy over and shaking it.

The backlash, gear ratio and timing numbers on this page are placeholder values taken from other people's published builds. They will be replaced by measurements of the real toy.

One interface, three backends

A single interface defines the skills: grasp a knob, rotate it, release, observe the pen, take a photo. Drawing and calibration code talks only to that interface.

  • Toy kernel. A model of the toy alone: knob angle to pen position with backlash, end stops and string strain. It runs in milliseconds and can inject faults such as a slipped grasp, which makes it the test bed for planning.
  • MuJoCo. Adds the arm, the gripper, contact and cameras. The arm finds the board from fiducial markers, grips each knob and turns it.
  • Real arm. Sends the same calls to the arm's motion server, inside a motion envelope that a person approves.

The backlash model

For each axis, the knob angle is θ and the angle of the internal pulley is φ. The pen sits at k·φ, and the gap between the two is e = θ − φ.

  • While the gap is inside the dead zone, the pen does not move.
  • Through a short transition zone, the gain ramps from 0 to 1.
  • At the full gap δ, the pulley follows the knob rigidly.

Once the slack is taken up in direction s, the pen position is k·(θ − s·δ) + c. The drawer therefore adds 2δ of knob rotation to the first turn after each reversal. Calibration turns each knob back and forth and fits k and δ from the pen positions the camera measures.

Grasping and turning in MuJoCo

The 6-DoF Gen3 model is generated from Kinova's own xacro file, because MuJoCo Menagerie ships only the 7-DoF arm.

A damped least-squares IK solver places the fingertips over a knob with the tool pointing straight down. It constrains five degrees of freedom and leaves rotation about the tool axis free. For a tool pointing down, that free rotation is joint 6, which is the joint that then turns the knob.

Straight-line moves are cut into 1 cm pieces. A single joint-space move bows sideways by several millimetres, enough to land a finger on the knob.

Seeing a grey line on a grey screen

The extractor rectifies the screen from its four corners and takes the median of a 10-frame burst. It keeps only pixels that are darker than the screen on both sides of a short line segment, so the edges of glare patches do not count. It then divides by local brightness, marks saturated glare as unknown and thresholds with hysteresis.

The browser demo

The demo at the top of this page is the same MuJoCo scene, compiled to WebAssembly and running in your browser. Nothing is prerecorded, and there is no server.

I ported the drawer, the IK solver, the motion code and the toy model from Python to JavaScript. On the same command sequence, the port reproduces the Python backend's knob angles to within 0.0001 rad.

The demo limits what you can draw to what the robot can do: one unbroken line of horizontal and vertical steps, up to 255 mm long. It draws open loop, and it reads the board position from the simulator instead of from the camera.

What is next

  • Measure the real toy's gear ratio and backlash, by hand and then with the arm.
  • Make the first drawing on hardware, then add closed-loop correction from the scene camera.
  • Add an LLM agent that plans drawings and corrects them from what the camera sees.
